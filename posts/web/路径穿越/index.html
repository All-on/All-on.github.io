路径穿越

路径遍历也称为目录遍历。这些漏洞使攻击者能够读取运行应用程序的服务器上的任意文件。

读取任意文件#

一个购物应用，显示待售商品图片。这可能会加载使用以下HTML的图片：

<img src="/loadImage?filename=218.png">

loadImage URL 接受一个 filename 参数，并返回指定文件的内容。图像文件存储在磁盘上的 /var/www/images/位置。要返回图像，应用程序将请求的文件名附加到该基目录，并使用文件系统 API 读取文件的内容。换句话说，应用程序从以下文件路径读取：

1/var/www/images/218.png

该应用程序未对路径遍历攻击实施任何防御。因此，攻击者可以请求以下 URL 从服务器的文件系统中检索 /etc/passwd 文件：

1https://insecure-website.com/loadImage?filename=../../../etc/passwd

在 Windows 上，../ 和 ..\ 都是有效的目录遍历序列。以下是针对基于 Windows 的服务器的等效攻击示例：

1https://insecure-website.com/loadImage?filename=..\..\..\windows\win.ini

绕过#

许多将用户输入输入到文件路径中的应用程序，会实现对路径穿越攻击的防御。这些通常可以绕过。

绝对路径#

遍历序列被绝对路径旁通阻断，传统的方式会显示文件不存在。因此，用文件系统根节点的绝对路径，比如 filename=/etc/passwd，直接引用文件，无需任何遍历序列。

非递归过滤#

如果是以非递归的方式将 ../ 替换为空，那么可以使用嵌套的遍历序列，比如 ....// 或 ....\/。当内层序列被剥离后，这些会恢复为简单的遍历序列。类似于双写绕过。

URL 编码绕过#

在某些情况下，例如在 URL 路径中或在 multipart/form-data 请求的 filename 参数中，Web 服务器可能会在将输入传递给应用程序之前剥离任何目录遍历序列。有时可以通过对 ../ 字符进行 URL 编码，甚至双重 URL 编码来绕过这种类型的清理。这分别会得到 %2e%2e%2f 和 %252e%252e%252f。各种非标准编码，例如 ..%c0%af （使用UTF-8 过长编码）或 ..%ef%bc%8f（全角斜杠），也可能有效。

路径起始验证#

应用程序可能要求用户提供的文件名以预期的基文件夹开头，比如 /var/www/images。在这种情况下，可能包含所需的基础文件夹，并搭配合适的遍历序列。比如：

1filename=/var/www/images/../../../etc/passwd

例如，图片显示 ?filename=/var/www/images/8.jpg，如果直接用 ?filename=../../../etc/passwd，会提示 “Missing parameter ‘filename’”。这可不是因为缺少 8.jpg，而是因为图像存储的位置没有说清楚，也就是起始地址。

验证文件扩展名#

应用程序可能要求用户提供的文件名以预期的文件扩展名结尾，例如 .png。在这种情况下，可能可以使用空字节来在所需扩展之前有效终止文件路径。例如：

1filename=../../../etc/passwd%00.png
