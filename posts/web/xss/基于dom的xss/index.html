在 document.write 接收器中使用 location.search源的 DOM XSS#

location.search是获取当前 URL 中问号后面的查询参数部分。document.write()是JavaScript 中用于动态向网页中写入内容的函数，它可以将文本或 HTML 直接插入到网页的文档中。再介绍2个img标签常用的函数：

  • <img src=xxx οnerrοr=" ">：当src=“xxx” 是不存在或无法加载的资源时，浏览器会触发 onerror 事件，可以利用图片加载失败触发 JavaScript 执行
  • <img src=xxx οnlοad=" ">：当src=“xxx” 是有效且能正常加载的资源时，浏览器会触发 onload 事件，可以利用图片加载成功触发 JavaScript 执行

例如，搜索的参数xxx被这样嵌入： <img src="/resources?SearchTerms=xxx"> 那么，可以选择直接跳出标签：

1"><svg onload=alert(1)>

包含于select元素中注入的 DOM XSS#

在某些情况下，所写内容包含一些需要在漏洞利用时考虑的相关上下文。例如，会使用StoreID向 URL 添加查询参数并输入随机字母数字字符串作为其值，该字符串现在被列为下拉列表中的选项之一。可以确认storeId参数值已放置在选择元素中：<select>...<option selected=>aaa</option>。因此，可以构造 URL 进行XSS：

1&storeId="></select><img%20src=1%20onerror=alert(1)>

在 innerHTML 接收器中使用 location.search源的 DOM XSS#

innerHTML用于读取或设置元素的 HTML 内容。innerHTML sink不接受任何现代浏览器中的script元素，svg onload事件也不会触发。这意味着需要使用诸如img或iframe这样的替代元素。事件处理程序如onload和onerror可以与这些元素结合使用。例如：

element.innerHTML='... <img src=1 onerror=alert(document.domain)> ...'

于是可以这样构造一个简单的payload：

1<img src=1 onerror=alert(1)>

jQuery 锚点的 href 属性#

使用 URL 查询参数（location.search）作为输入，jQuery 把它设置到锚点（<a>标签）的 href 属性上，导致 DOM 型 XSS 漏洞。 如果正在使用诸如 jQuery 这样的 JavaScript 库，需要注意可能改变页面上 DOM 元素的点。例如，jQuery 的 attr() 函数可以修改 DOM 元素的属性。如果数据是从用户可控的来源（例如 URL）读取的，然后传递给 attr() 函数，那么可能会操作传入的值以引发 XSS。例如，下面的 JavaScript 代码使用来自 URL 的数据来更改锚元素的 href 属性：

1$(function() {
2	$('#backLink').attr("href",(new URLSearchParams(window.location.search)).get('returnUrl'));
3});

可以通过修改 URL 来利用这一点，使 location.search 的来源包含一个恶意的 JavaScript URL。在页面的 JavaScript 将这个恶意 URL 应用于返回链接的 href 后，点击返回链接就会执行它：

?returnUrl=javascript:alert(document.domain)

jQuery的选择器函数$()#

另一个需要注意的潜在漏洞是 jQuery 的 $() 选择器函数，它可以被用来将恶意对象注入到 DOM 中。jQuery 曾经非常流行，而一个经典的 DOM XSS 漏洞是由于网站在执行动画或自动滚动到页面特定元素时，将该选择器与 location.hash 源（获取当前 URL 中 # 后面的片段标识符，即锚点）一起使用所引起的。这种行为通常通过易受攻击的 hashchange 事件（当网页 URL 的 #（hash）部分发生变化时，这个事件会被触发）处理程序实现，类似如下所示：

1$(window).on('hashchange', function() {
2	var element = $(location.hash);
3	element[0].scrollIntoView();
4});

由于哈希是用户可控的，攻击者可以利用这一点将 XSS 向量注入到 $() 选择器中。较新版本的jQuery通过防止输入以哈希字符（#）开头时向选择器注入HTML来修补这一漏洞。 要实际利用这个经典漏洞，需要找到一种方法在没有用户交互的情况下触发 hashchange 事件。实现这一点最简单的方法之一是通过 iframe 传递漏洞利用代码：

1<iframe src="https://vulnerable-website.com#" onload="this.src+='<img src=1 onerror=alert(1)>'">

在这个例子中，src 属性指向具有空哈希值的易受攻击页面。当 iframe 加载时，XSS 向量会被附加到哈希上，从而触发 hashchange 事件。

例如，在钓鱼页面（服务器）上发送如下的payload，将结果转变为受害者的ID就行：

1<iframe src="https://YOUR-LAB-ID.web-security-academy.net/#" onload="this.src+='<img src=x onerror=print()>'"></iframe>

AngularJS 中的 DOM XSS#

如果使用像 AngularJS 这样的框架，可能可以在没有尖括号或事件的情况下执行 JavaScript。当网站在 HTML 元素上使用 ng-app 属性时，它将由 AngularJS 处理。在这种情况下，AngularJS 会执行直接出现在 HTML 中或属性内的双大括号里的 JavaScript。 例如，输入：

1{{$on.constructor('alert(1)')()}}

在 AngularJS 的模板中，{{ }} 内的表达式会在当前 $scope 上下文中求值。$on 是 $scope 对象上的一个方法（通常用于监听事件），所以这里访问的是 $scope.$on 函数。每个 JavaScript 函数（实际上是所有对象）都有一个 constructor 属性，指向创建该对象的构造函数。$on 是一个函数，它的构造函数是 Function。因此 $on.constructor 就是全局的 Function 构造函数。

反射 DOM XSS#

在反射 DOM XSS 漏洞中，服务器处理请求数据，并将数据回响到响应中。反射数据可以被放入 JavaScript 字符串文字，或 DOM 中的数据项，如表单字段。页面上的脚本随后以不安全的方式处理反射数据，最终将其写入危险的汇入。比如：

1eval('var data = "reflected string"');

例如，发现代码利用 innerText 将服务器返回的内容插入到页面，纯文本，所以无法执行。此外双引号还被转义(\")。假如输入aaa，那么响应的结果是： {"searchTerm":"aaa", "results":[]} 在这种情况下继续进行XSS，于是输入\"-alert(1)}//，结果就变成了下面的响应，成功弹出了弹窗： {"searchTerm":"\\"-alert(1)}//", "results":[]} 其中 - 是减号运算符，左侧是刚解析出的字符串值（一个反斜杠），右侧是 alert(1) 的返回值。在执行减法时，会先计算右侧 alert(1)，于是弹窗出现。双反斜杠 // 作为注释符号，将后面的内容全部注释掉。

存储 DOM XSS#

网站也可能将数据存储在服务器上，并将其反映在其他地方。在存储的DOM XSS漏洞中，服务器接收一个请求的数据，将其存储，然后在后续响应中包含该数据。后期响应中的脚本包含一个汇入，然后以不安全的方式处理数据。

1element.innerHTML = comment.author

例如，网站使用 JavaScript的replace()函数对尖括号进行编码。当第一个参数是字符串时，该函数仅替换第一次出现。于是，先让开头简单地包含一组额外的尖括号来利用此漏洞。这些尖括号将被编码，但任何后续尖括号将不受影响：

1<><img src=1 onerror=alert(1)>
