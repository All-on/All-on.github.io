一、进程模型#

1. 多道程序设计#

  • 定义：多个程序同时进入内存并运行，提高系统效率。
  • 特点：并发执行、资源共享、执行顺序不确定。

2. 进程的定义与作用#

  • 进程：程序的一次执行过程，是正在运行程序的抽象。
  • 作用：
    • 将CPU抽象为多个虚拟CPU；
    • 是系统资源分配的基本单位；
    • 每个进程有独立的地址空间。

3. 进程的组成#

  • 进程映像 = 程序 + 数据 + 栈 + PCB
  • PCB（进程控制块）：描述进程的所有属性，是进程存在的唯一标志。
  • PCB内容：
    • 进程ID、状态、优先级、地址空间、打开文件、寄存器等。

4. 进程状态与转换#

  • 基本状态：
    • 运行（Running）
    • 就绪（Ready）
    • 阻塞/等待（Blocked/Waiting）
  • 其他状态：
    • 创建（New）、终止（Terminated）、挂起（Suspend）
  • Linux状态：TASK_RUNNING、TASK_INTERRUPTIBLE、TASK_ZOMBIE等

5. 进程控制#

  • 原语：不可中断的操作，如创建、撤销、阻塞、唤醒等。
  • 创建过程：分配PID、PCB、地址空间，初始化并加入就绪队列。
  • 系统调用：
    • UNIX：fork()、exec()、wait()、exit()
    • Windows：CreateProcess、ExitProcess

6. 进程地址空间#

  • 虚拟地址空间：每个进程拥有独立的虚拟地址空间。
  • 结构：代码段、数据段、堆、栈、共享库、内存映射文件。
  • 查看方法：/proc/PID/maps

二、线程模型#

1. 为什么引入线程？#

  • 应用需求：如字处理器、Web服务器
  • 开销小：创建、撤销、切换、通信开销远小于进程
  • 性能提升：更好利用多核，支持并发I/O

2. 线程的定义与属性#

  • 线程：进程中执行的实体，是CPU调度的基本单位。
  • 属性：
    • 有状态、上下文、栈；
    • 共享进程的地址空间和资源；
    • 可创建、撤销其他线程。

3. 线程的实现方式#

类型特点
用户级线程在用户空间管理，切换快，但会因系统调用阻塞整个进程
核心级线程由内核管理，可多核并行，但切换开销大
混合模型用户线程映射到内核线程，平衡灵活性与性能

三、协程（简要）#

1. 定义#

协程是一种用户态的轻量级线程，由程序员控制在用户空间进行调度，而不是由操作系统内核进行调度。

2. 核心特征#

  • 用户态执行：协程的创建、切换和销毁都在用户空间完成，不需要陷入内核态

  • 协作式调度：协程主动让出CPU控制权，而不是被系统强制抢占

  • 低成本：协程切换只需保存少量寄存器上下文，开销远小于线程切换(约100-200ns)

  • 共享栈/独立栈：有无栈协程两种实现方式

  • N:M映射：多个协程可以映射到少量系统线程上执行

3. 与线程的关键区别#

特性系统线程协程
调度方操作系统内核应用程序/程序员
切换开销大(需内核介入)小(纯用户态操作)
内存占用大(通常MB级别)小(通常KB级别)
数量上限数百至数千数十万至上百万

4. 为什么引入协程#

1. 解决线程模型的痛点#
  • 内存消耗：万级线程消耗数十GB内存，而协程仅需MB级
  • 切换开销：线程切换涉及内核态切换，成本高昂
  • 并发瓶颈：C10K/C100K问题下线程模型达到性能极限
2. 提升I/O密集型应用性能#
  • 在等待I/O时，协程可主动让出CPU，让其他协程继续工作
  • 单线程内可运行大量协程，极大提升吞吐量
3. 简化异步编程#
  • 用同步的编码风格实现异步的执行效果
  • 避免"回调地狱"，提高代码可读性和可维护性
适用场景：#
  • 高并发网络服务：Web服务器、API网关、微服务
  • I/O密集型任务：数据库访问、文件读写、网络请求
  • 游戏服务器：大量用户连接管理

四、重点概念与关键词#

1. 进程特性#

并发性、动态性、独立性、制约性、异步性

2. 可再入程序#

纯代码，可被多个进程同时调用，不修改自身。

3. 写时复制（Copy-On-Write, COW）#

fork() 时不复制全部内存，只在写入时复制，提升性能。

  • 传统方式：fork() 立即复制整个地址空间 → 开销大
  • COW优化：
    • fork() 后，父子进程共享同一物理内存
    • 将共享页面标记为只读
    • 当任一进程尝试写入时，才复制该页面，并为写入进程创建副本
  • 优点：
    • 大幅减少fork()的内存开销和时间延迟
    • 适用于fork() + exec()的常见场景（子进程往往立即执行新程序，无需复制）

4. 内存映射：mmap()#

  • 将文件或匿名内存映射到进程地址空间。
  • 标志：MAP_PRIVATE、MAP_SHARED、MAP_ANON
