一、 调度概述与层次#

1. 调度的三个层次#

  • 长程调度（作业调度）：决定是否将新进程加入当前活跃进程集合。
  • 中程调度：负责进程在内存和外存之间的交换（Swapping）。
  • 短程调度（微观调度）：决定哪个就绪进程/线程获得CPU使用权。时间尺度为毫秒级，要求高效。

2. 调度要解决的三个核心问题 (What, When, How)#

  • What：依据什么原则选择进程 -> 调度算法
  • When：在什么时候进行调度 -> 调度时机
  • How：如何分配CPU -> 上下文切换过程

3. CPU调度时机#

  • 关键事件：进程创建/退出、I/O请求/完成、阻塞/唤醒、时间片用完、中断/异常。
  • 核心时机：在内核处理完中断/异常/系统调用后，返回到用户态之前的最后时刻。

4. 上下文切换#

  • 过程：保存当前进程的硬件状态（到PCB）-> 切换地址空间 -> 恢复新进程的硬件状态。
  • 开销：
    • 直接开销：执行切换操作本身消耗的CPU时间。
      • 保存/恢复寄存器的CPU时间。
      • 切换地址空间（如更新页表基址寄存器），这个操作尤其昂贵。
    • 间接开销：Cache、TLB、Buffer Cache失效带来的性能损失。

二、 调度算法设计目标与原则#

1. 不同系统的目标#

系统类型 用户关心 系统关心
批处理系统 周转时间 吞吐量、CPU利用率
交互式系统 响应时间 均衡性、公平性
实时系统 最后期限、可预测性 截止时间保证

2. 调度算法的衡量指标#

  • 周转时间：从提交到完成的时间。
  • 响应时间：从提交到第一次响应的时间。
  • 吞吐量：单位时间内完成的进程数。
  • CPU利用率：CPU做有效工作的时间比例。
  • 等待时间：进程在就绪队列中等待的总时间。
  • 公平性：每个进程都能获得合理的CPU时间。
  • 可预测性：进程执行的延迟是可预期的。

3. 设计调度算法的要点#

  • 进程优先级：静态（创建时确定） vs 动态（运行时调整）。
  • 就绪队列组织：如何按优先级组织队列。
  • 抢占 vs 非抢占：
    • 抢占式：高优先级进程可剥夺当前进程的CPU。
    • 非抢占式：进程一旦运行，除非主动放弃，否则一直运行。
  • 进程类型：
    • I/O密集型：频繁I/O，应获得更高优先级以提升设备利用率。
    • CPU密集型：长时间计算，可分配较长的时间片以减少切换开销。
  • 时间片选择：需在响应时间和切换开销之间权衡。

三、 典型的调度算法#

1. 批处理系统调度算法#

算法 思想 特点
FCFS 先来先服务 公平、简单；对短作业不利，易导致"护航效应"
SJF 最短作业优先 平均周转时间最短；可能导致长作业"饥饿"，需预知运行时间
SRTN 最短剩余时间优先 SJF的抢占式版本
HRRN 最高响应比优先 R=1+等待时间/运行时间 折衷方案，兼顾等待时间和运行时间

2. 交互式系统调度算法#

算法 思想 特点
RR 时间片轮转 公平，响应快；时间片大小对性能影响大
优先级调度 优先级高的先运行 简单；可能导致低优先级进程"饥饿"
多级队列 不同队列用不同策略 分类处理，灵活性高
多级反馈队列 进程可在队列间移动 综合型算法，兼具RR和优先级的优点，对I/O型进程友好

3. 实时系统调度算法#

  • 目标：满足最后期限，保证可预测性。
  • 策略：通常采用基于优先级的抢占式调度。

4. 算法比较摘要#

算法 决策模式 优点 缺点
FCFS 非抢占 公平、简单 平均等待时间长
RR 抢占 响应快、公平 上下文切换开销大
SJF/SRTN 非抢占/抢占 平均周转时间最短 可能导致饥饿，需预测未来
HRRN 非抢占 平衡性好
多级反馈队列 抢占 灵活，通用性好 可能复杂

四、 高级主题与实例系统#

1. 优先级反转问题#

  • 问题：中优先级进程阻止高优先级进程运行（因为低优先级进程持有高优先级进程所需的资源）。
  • 解决方案：优先级继承、优先级天花板协议。

2. 机制与策略分离#

  • 机制：如何实现调度（如上下文切换、队列管理）。
  • 策略：选择哪个进程运行（如调度算法）。
  • 分离好处：提高系统灵活性，允许更改策略而不影响机制。

3. 实例操作系统调度算法#

  • Windows：基于动态优先级的抢占式多任务调度。调度单位是线程，支持优先级提升（如I/O完成后）以防止饥饿。
  • Linux：
    • 演化：O(1)调度器 -> RSDL -> CFS（完全公平调度器）。
    • CFS核心：不再区分交互式与批处理进程，而是追求完全公平。
    • 实现：使用红黑树以虚拟运行时间（vruntime） 为键值，每次选择vruntime最小的进程运行。vruntime的增长速度与优先级成反比。

4. 多处理器调度#

  • 挑战：负载均衡 vs 缓存亲和性（尽量减少进程在CPU间迁移）。
  • 分配方式：
    • 静态分配：每个CPU有自己的队列，开销小，但可能负载不均。
    • 动态分配：共享一个公共队列，负载均衡好，但调度开销和同步成本高。

五、 重点概念辨析#

  • 调度时机 vs 调度过程：时机是“何时做”，过程是“如何做（切换）”。
  • 吞吐量 vs 周转时间：吞吐量是系统视角（活干得多快），周转时间是用户视角（我的活多久干完）。
  • 响应时间 vs 截止时间：响应时间是交互式系统的延迟要求，截止时间是实时系统的硬性规定。
  • 抢占式 vs 非抢占式：根本区别在于调度是否由运行进程自身主动引发。
