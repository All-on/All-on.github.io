1. 基本概念#

  • 死锁：一组进程互相等待对方占有的资源，导致所有进程无法推进。
  • 活锁：进程不断改变状态但无法取得进展（如反复重试）。
  • 饥饿：某个进程长期得不到资源，由于调度策略不公平导致。

2. 产生死锁的四个必要条件#

  • 互斥使用（资源独占）
  • 占有且等待（部分分配）
  • 不可抢占（资源只能自愿释放）
  • 循环等待（存在进程等待环路）

3. 资源分配图（RAG）#

  • 用于描述系统资源分配与请求关系。
  • 结点：进程（○）、资源（□，实例为●）。
  • 边：分配边（资源→进程）、请求边（进程→资源）。
  • 死锁判定：
    • 有环不一定死锁（资源有多个实例时）。
    • 若每个资源类只有一个实例，环路 ⇔ 死锁。
  • 化简方法：逐步移除可满足的进程及其边，若可完全化简则无死锁。

4. 死锁解决方案#

（1）死锁预防（静态策略，破坏必要条件）#

  • 破坏互斥：SPOOLING 技术（如打印机守护进程）。
  • 破坏占有且等待：
    • 一次性申请所有资源。
    • 申请新资源前释放已占有资源。
  • 破坏不可抢占：允许操作系统抢占资源（适用于CPU、内存）。
  • 破坏循环等待：资源有序分配法（按编号递增顺序申请）。

（2）死锁避免（动态检查，银行家算法）#

  • 安全状态：存在一个安全序列，使所有进程能完成。
  • 银行家算法步骤：
    1. 检查请求是否 ≤ Need 且 ≤ Available。
    2. 试探分配，检查安全性：
      • 寻找可完成的进程（Need ≤ Work）。
      • 回收资源，标记完成。
      • 若所有进程可完成，则安全。
    3. 若安全则分配，否则恢复并等待。

（3）死锁检测与解除#

  • 检测时机：定时检测、资源利用率下降时检测。
  • 解除方法：
    • 撤销所有死锁进程。
    • 进程回退（Rollback）再启动。
    • 逐一撤销或抢占资源直至死锁解除。

5. 哲学家就餐问题（经典死锁模型）#

问题描述：#

  • 5个哲学家，5根筷子，需同时拿到左右筷子才能进食。

解决方案：#

  1. 信号量方案（易死锁）：每人先拿左再拿右 → 可能循环等待。
  2. 资源有序分配：奇数号先左后右，偶数号先右后左。
  3. 限制并发数：最多允许4人同时拿筷子。
  4. 管程（Monitor）或状态机方案：
    • 仅当左右筷子可用时才分配。
    • 通过状态（思考、饥饿、进食）协调。
