一、文件系统基本概念#

1. 什么是文件？#

  • 定义：一组带标识（文件名）、在逻辑上有完整意义的信息项序列。
  • 信息项：构成文件内容的基本单位（字节或记录），有顺序关系。
  • 意义：由文件建立者和使用者解释。
  • 本质：文件是对磁盘的抽象。

2. 文件系统的作用#

  • 统一管理信息资源（存储、检索、更新）。
  • 提供共享、保护手段，方便用户使用。
  • 管理磁盘空间（分配与回收）。
  • 实现文件名到磁盘空间的映射。
  • 提供与I/O系统的统一接口。

3. 文件分类（UNIX）#

  • 普通文件：用户信息，ASCII或二进制。
  • 目录文件：管理系统文件。
  • 特殊文件：
    • 字符设备文件（终端、打印机等）。
    • 块设备文件（磁盘）。
  • 管道文件、套接字、符号链接文件等。

4. 文件的逻辑结构#

  • 流式文件：字节序列。
  • 记录式文件：记录序列（可顺序或索引组织）。
  • 树形结构：支持层次化数据。

5. 文件的存取方式#

  • 顺序存取：按字节依次读写。
  • 随机存取：可直接跳转到任意位置（如UNIX的SEEK）。

二、文件系统的实现#

1. 存储介质与磁盘块#

  • 扇区：物理存储单位，保证写入原子性。
  • 磁盘块（簇）：逻辑存储单位，由若干扇区组成，是分配和传输的基本单位。

2. 文件属性与FCB#

  • 文件控制块（FCB）：操作系统管理文件的数据结构，存放文件所有属性（元数据）。
  • 常见属性：文件名、大小、位置、权限、时间戳等。

3. 文件操作#

  • 基本操作：CREATE、DELETE、OPEN、CLOSE、READ、WRITE、SEEK等。
  • 打开模式：进程需先“打开”文件才能访问。

4. 文件目录#

  • 目录文件：存放目录项的特殊文件。
  • 目录项：可以是FCB或指向FCB的指针。
  • 树形目录结构：
    • 绝对路径 vs 相对路径。
    • 当前目录（工作目录）。
  • 目录操作：CREATE、DELETE、OPENDIR、READDIR等。

三、文件系统的磁盘布局#

1. 基本术语#

  • 磁盘分区：物理磁盘划分为独立部分。
  • 文件卷：逻辑分区，可跨磁盘。
  • 格式化：在卷上建立文件系统的过程。

2. 磁盘上的布局#

  • 引导区：引导操作系统的信息。
  • 卷信息：块数、大小、空闲块指针等。
  • 目录结构：目录文件的存放位置。
  • 用户文件：实际数据存储区。

3. 实现细节#

1. 如何启动所存储的操作系统？#

磁盘的引导区（通常为第一个扇区）存储引导程序和分区表。计算机启动时，BIOS/UEFI 读取主引导记录（MBR）或GPT，找到活动分区，加载该分区的引导扇区，进而启动操作系统。

2. 磁盘是怎样管理的？如何获取磁盘信息？#

通过卷（分区）信息块（如超级块、BPB）记录：

  • 块数、块大小
  • 空闲块数量与指针
  • 文件系统类型、状态等

操作系统读取这些元数据来管理磁盘空间和文件。

四、文件的物理结构（磁盘结构）#

1. 连续结构#

  • 文件存放在连续的磁盘块中。
  • 优点：简单、高效、支持随机存取。
  • 缺点：外部碎片、文件不易动态增长。

2. 链接结构#

  • 文件存放在不连续的块中，通过指针链接。
  • 变体：文件分配表（FAT）。
  • 优点：无外部碎片、支持动态增长。
  • 缺点：随机存取慢、指针占用空间。

3. 索引结构#

  • 为每个文件建立索引表，存放块号。
  • 优点：支持随机存取、动态增长。
  • 缺点：索引表占用额外空间。
  • 多级索引：UNIX采用三级索引结构（直接+间接）。

五、目录文件的组织与检索#

1. 组织方式#

  • 顺序表：简单，查找慢。
  • 散列表：查找快，需处理冲突。
  • B/B+树：NTFS采用B+树组织目录项。

2. 目录检索#

  • 步骤：
    1. 文件名 → 目录项（FCB）。
    2. FCB → 磁盘地址。
  • 路径解析：绝对路径 vs 相对路径。

3. 目录项分解（改进检索速度）#

  • 符号目录项：文件名 + 文件号。
  • 基本目录项：其余FCB信息。
  • 优点：减少访盘次数，提高检索速度。

六、文件系统实例#

1. UNIX文件系统#

  • FCB = 目录项 + I节点。
  • I节点：存放文件元数据（不含文件名）。
  • 多级索引结构：支持大文件。

2. FAT文件系统#

  • 簇：基本分配单位（多个扇区）。
  • 文件分配表（FAT）：描述簇的分配状态和链接关系。
  • 目录项：32字节，包含文件名、属性、起始簇号等。
  • FAT16 vs FAT32：FAT32支持更大卷、长文件名。

七、磁盘空间管理#

1. 管理方法#

  • 位图法：每个块对应一个二进制位。
  • 空闲块表：记录所有空闲块。
  • 空闲块链表：链接所有空闲块。
  • 成组链接法：UNIX采用，高效管理空闲块组。

2. 地址计算#

  • 已知块号 → 磁盘地址（柱面、磁头、扇区）。
  • 已知磁盘地址 → 块号。

八、内存中的数据结构（UNIX为例）#

1. 用户打开文件表#

  • 每个进程一个，记录打开文件的状态。
  • 包含文件描述符、打开方式、读写指针和系统打开文件表入口。

2. 系统打开文件表#

  • 整个系统一个，存放已打开文件的FCB（或I节点）信息、引用计数和修改标志。
  • 引用计数：支持文件共享。

3. 文件描述符与重定向#

  • 文件描述符：非负整数，代表进程内打开的文件。
  • 重定向：通过dup2等系统调用实现。

九、文件操作实现流程#

1. 创建文件#

  • 在目录中建立目录项。
  • 分配磁盘块。

2. 打开文件#

  • 根据路径名查找目录项。
  • 检查权限，建立内存结构（用户/系统打开文件表）。
  • 返回文件描述符。

3. 读文件#

  • 根据文件描述符找到FCB。
  • 检查权限，计算逻辑块号 → 物理块号。
  • 读磁盘 → 缓冲区 → 用户内存。

4. 指针定位（SEEK）#

  • 修改用户打开文件表中的读写指针。

十、文件共享与挂载#

1. 文件共享#

  • 硬链接：多个目录项指向同一个I节点，链接计数管理。
  • 软链接（符号链接）：特殊文件，内容为目标文件路径。比如，快捷方式。

硬链接实现细节#

1. 硬链接时是FCB中直接给出文件地址吗？#

不是。硬链接是多个目录项指向同一个 inode（索引节点）。目录项中只存储文件名 + inode号，不直接存储文件地址。文件地址（磁盘块列表）存储在 inode 中。

2. 删除文件时怎样考虑？#

inode 中有一个链接计数（link count），记录有多少个目录项指向它。删除一个硬链接（如rm命令）时：

  1. 链接计数减1。
  2. 若链接计数 > 0，只删除该目录项，文件数据保留。
  3. 若链接计数 = 0，表示无任何目录项指向该文件，系统才会真正删除文件数据（释放inode和磁盘块）。

2. 挂载（Mount）#

  • 将一个文件系统连接到另一个文件系统的目录下。
  • 挂载点：目标文件系统中的目录。
