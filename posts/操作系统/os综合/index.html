2、open() 系统调用的完整过程#

当调用 open("file.txt", O_RDONLY) 时：

步骤1：路径解析与inode查找#

  • 内核解析路径名，查找文件
  • 找到文件的 inode（存储在磁盘上，可能缓存于内存）
  • 验证权限（是否可读等）

步骤2：创建系统打开文件表条目#

这里不太准确。应该说，在[[第7章 文件系统1#2. 系统打开文件表|系统打开文件表]]中查找。如果没有对应的系统打开文件表条目，则创建并将引用计数置为1；否则将引用计数加1。

1// 内核内部创建file结构体（系统打开文件表条目）
2struct file *filp = kmem_cache_alloc(filp_cachep, GFP_KERNEL);
3filp->f_path.dentry = dentry;  // 目录项
4filp->f_op = inode->i_fop;     // 文件操作函数表
5filp->f_mode = mode;           // 打开模式
6filp->f_pos = 0;               // 文件指针位置
7filp->f_count = 1;             // 引用计数

这是系统级别的数据结构，记录文件打开状态，所有进程共享

步骤3：更新用户打开文件表#

1// 每个进程有自己的files_struct（用户打开文件表）
2// 在其中找到一个空闲的文件描述符fd
3int fd = get_unused_fd_flags(flags);
4
5// 将用户打开文件表fd数组的第fd项指向系统打开文件表条目
6current->files->fd_array[fd] = filp;

这里的 current->files 就是当前进程的 files_struct

步骤4：返回fd#

  • 返回给用户的fd不是指针，而是一个数组索引
  • 例如返回3，意味着用户打开文件表的第3项指向了系统打开文件表的一个条目

3、用户打开文件表的真实结构#

在Linux中：

 1struct files_struct {
 2    atomic_t count;              // 引用计数
 3    struct fdtable *fdt;         // 指向文件描述符表
 4    ...
 5};
 6
 7struct fdtable {
 8    unsigned int max_fds;        // 最大文件描述符数
 9    struct file **fd;            // 这是一个指针数组，fd[0], fd[1], ...
10};

关键理解：

  • fd[3] 是一个 指针，指向系统打开文件表中的 struct file
  • 用户得到的 fd=3 是这个数组的索引
  • 用户后续使用fd时，内核通过 current->files->fdt->fd[fd] 找到对应的 struct file

4、完整流程图#

二、read函数#

1、整体流程概览#

 1用户态进程调用read(fd, buf, count)
 2    ↓
 3触发int 0x80系统调用（陷入内核）
 4    ↓
 5系统调用总入口system_call()
 6    ↓
 7调用sys_read()系统调用处理函数
 8    ↓
 9根据fd找到file结构体（系统打开文件表）
10    ↓
11根据file结构体找到inode（目录项）
12    ↓
13计算要读取的逻辑块号（文件偏移→逻辑块）
14    ↓
15通过inode索引结构找到物理块号（逻辑块→物理块）
16    ↓
17检查页缓存，如果命中则直接复制数据
18    ↓
19如果未命中，向块设备层提交I/O请求
20    ↓
21磁盘读取数据到页缓存，触发中断
22    ↓
23中断处理完成，数据就绪
24    ↓
25将数据从页缓存复制到用户缓冲区buf
26    ↓
27返回用户态，继续执行

2、详细步骤分解#

阶段1：用户态触发系统调用#

从这一步开始，一直到阶段，都是具体的[[第2章 运行环境与运行机制#2. 系统调用执行流程（以Linux x86的write为例）|系统调用]]的流程。

1// 用户程序
2char buffer[1024];
3int fd = open("file.txt", O_RDONLY);
4read(fd, buffer, 1024);  // 触发系统调用

C库包装函数执行：

1; C库read包装函数的汇编实现
2mov eax, 3        ; 系统调用号3 = sys_read
3mov ebx, [esp+4]  ; fd参数
4mov ecx, [esp+8]  ; buffer地址
5mov edx, [esp+12] ; count大小
6int 0x80          ; 触发软中断，进入内核态
7ret

阶段2：硬件中断处理（CPU级）#

  1. CPU响应int 0x80指令：

    • 从用户态（R3）切换到内核态（R0）
    • 保存用户态上下文到内核栈：
      1压栈顺序（从高地址到低地址）：
2SS（用户栈段寄存器）
3ESP（用户栈指针）
4EFLAGS（标志寄存器）
5CS（代码段寄存器）
6EIP（下一条指令地址，即返回地址）

  2. 查找中断描述符表（IDT）：

    1// IDT第0x80项在Linux初始化时设置
2IDT[0x80] = {
3    .offset = system_call,  // 处理函数入口
4    .segment_selector = KERNEL_CS,
5    .type = TRAP_GATE,
6    .DPL = 3  // 用户态可调用
7};

  3. 切换到内核栈：

    • 从TSS（任务状态段）加载内核栈指针
    • 当前进程的task_struct->thread.esp0指向内核栈顶

阶段3：系统调用总入口system_call#

 1// arch/x86/kernel/entry_32.S
 2ENTRY(system_call)
 3    // 1. 保存完整上下文
 4    SAVE_ALL          // 将所有通用寄存器压栈
 5    
 6    // 2. 参数检查
 7    cmpl $(NR_syscalls), %eax
 8    jae badsys
 9    
10    // 3. 调用sys_read处理函数
11    call *sys_call_table(,%eax,4)  // eax=3 → sys_read
12    
13    // 4. 保存返回值
14    movl %eax, PT_EAX(%esp)
15    
16    // 5. 检查是否需要调度
17    jmp ret_from_sys_call

此时栈结构（从栈底到栈顶）：

 2ESP（用户栈指针）
 3EFLAGS
 4CS
 5EIP          <-- 中断硬件压栈
 6EAX
 7ECX
 8EDX
 9EBX
10ESP（原始）
11EBP
12ESI
13EDI          <-- SAVE_ALL压栈
14GS
15FS
16ES
17DS

阶段4：sys_read系统调用处理#

 1// fs/read_write.c
 2asmlinkage ssize_t sys_read(unsigned int fd, char __user *buf, size_t count)
 3{
 4    struct file *file;
 5    ssize_t ret = -EBADF;
 6    
 7    // 1. 根据fd找到file结构体
 8    file = fget(fd);  // 实际代码：current->files->fd_array[fd]
 9    if (!file)
10        goto out;
11    
12    // 2. 检查权限
13    if (!(file->f_mode & FMODE_READ))
14        goto out_fput;
15    
16    // 3. 调用虚拟文件系统（VFS）的读操作
17    ret = vfs_read(file, buf, count, &file->f_pos);
18    
19out_fput:
20    fput(file);  // 减少引用计数
21out:
22    return ret;
23}

关键步骤解析：

  1. fget(fd)：从当前进程的files_struct中通过fd索引找到file结构体指针
     1// 简化逻辑
 2struct file *fget(unsigned int fd)
 3{
 4    struct files_struct *files = current->files;
 5    struct file *file;
 6
 7    rcu_read_lock();
 8    file = files->fd_array[fd];  // 这就是fd的真实含义：数组索引
 9    if (file)
10        atomic_inc(&file->f_count);  // 增加引用计数
11    rcu_read_unlock();
12    return file;
13}

阶段5：VFS层处理vfs_read#

 1// fs/read_write.c
 2ssize_t vfs_read(struct file *file, char __user *buf, size_t count, loff_t *pos)
 3{
 4    ssize_t ret;
 5

 8        return -EBADF;

10    // 2. 调用文件系统的具体读方法

14}

三、helloworld程序#

1、HelloWorld程序执行全流程#

阶段1：编写和编译（用户态）#

1// hello.c
2#include <stdio.h>
3int main() {
4  printf("Hello, World!\n");
5  return 0;
6}

用户操作：

1gcc -o hello hello.c  # 编译

编译过程：

1hello.c → 预处理器 → 编译器 → 汇编器 → 链接器 → hello可执行文件

产物分析：

  • Windows：hello.exe（PE格式，Portable Executable）
  • Linux：hello（ELF格式，Executable and Linkable Format）

关键点：

  • 用户态：gcc运行在用户态
  • 涉及系统调用：文件读写（读取.c文件，写入可执行文件）
  • 硬件参与：CPU执行gcc进程，磁盘I/O

阶段2：Shell解析命令（用户态→内核态）#

用户输入：

1./hello

Shell内部处理流程：

 1// shell伪代码
 2int main() {
 3    while(1) {
 4        read_command();      // 读取用户输入"./hello"
 5        
 6        // 检查不是内置命令，需要创建新进程
 7        pid = fork();        // 系统调用，进入内核态
 8        if (pid == 0) {
 9            // 子进程
10            execve("./hello", argv, envp);  // 系统调用，进入内核态
11        } else {
12            // 父进程（shell）
13            waitpid(pid);     // 系统调用，等待子进程结束
14        }
15    }
16}

状态切换：

1用户态(shell) → fork() → 内核态 → 返回用户态(子shell)

阶段3：fork()创建子进程（内核态）#

内核执行：

 1// kernel/fork.c
 2SYSCALL_DEFINE0(fork)
 3{
 4    // 1. 分配新的task_struct（PCB）
 5    struct task_struct *p = copy_process(CLONE_FORK, ...);
 6    
 7    // 2. 复制父进程地址空间（写时复制）
 8    copy_mm(clone_flags, p);
 9    
10    // 3. 设置子进程返回值为0
11    p->thread.sp = (unsigned long) childregs;
12    childregs->ax = 0;  // 子进程fork()返回0
13    
14    // 4. 加入就绪队列
15    wake_up_new_task(p);
16    
17    return p->pid;  // 父进程返回子进程PID
18}

硬件参与：

  • MMU：设置页表，实现[[第3章 进程与线程模型#3. 写时复制（Copy-On-Write, COW）|写时复制（COW）]]机制
  • CPU：保存/恢复上下文

阶段4：execve()加载可执行文件（内核态）#

子进程调用：

1execve("./hello", NULL, NULL);

内核加载器工作：

 1// fs/exec.c
 2int do_execve(struct linux_binprm *bprm)
 3{
 4    // 1. 检查文件格式（ELF识别）
 5    retval = search_binary_handler(bprm);

 7    // 2. 设置新的地址空间
 8    setup_new_exec(bprm);
 9    
10    // 3. 加载程序段
11    load_elf_binary(bprm);

13    // 4. 设置入口点
14    start_thread(regs, elf_entry, bprm->p);
15}

关键机制：

  • 内存映射：将ELF文件的各个段映射到进程虚拟地址空间
  • 延迟加载：建立虚拟内存到文件的映射，但实际数据在访问时才加载
  • 页表设置：建立虚拟地址→物理地址的映射关系

涉及到进程调度。调度器选择该进程运行：

1// kernel/sched/core.c
2__schedule() {
3    // 1. 选择下一个要运行的进程

5

[[第4章 进程与线程调度#4. 上下文切换|上下文切换]]硬件操作：

 1; 保存当前进程寄存器
 2push %eax
 3push %ebx
 4...
 5; 切换页表（CR3寄存器）

阶段7：缺页异常处理（关键机制）#

当程序首次访问代码/数据时，触发缺页异常，涉及[[第6章 虚拟存储管理#九、内存映射文件（Memory-Mapped Files）|内存映射]]：

 1// 第一次执行main()函数时
 2// CPU尝试读取0x400100地址的指令
 3// 但该页尚未加载到物理内存
 4
 5// 触发缺页异常
 6void do_page_fault(struct pt_regs *regs, unsigned long error_code)
 7{
 8    // 1. 查找vm_area_struct
 9    vma = find_vma(mm, address);
10    
11    // 2. 如果是文件映射（如ELF代码段）
12    if (vma->vm_file) {
13        // 从磁盘读取对应页
14        filemap_fault(vma, &vmf);
15    }
16    
17    // 3. 建立页表映射
18    handle_mm_fault(vma, address, flags);
19}

数据流：

1CPU访问虚拟地址0x400100
2    ↓ 触发缺页异常（硬件自动）
3    ↓ CPU切换到内核态
4    ↓ 内核异常处理程序
5    ↓ 从磁盘hello文件读取.text段对应页
6    ↓ 加载到物理内存
7    ↓ 更新页表
8    ↓ 返回用户态，重新执行指令

4、核心要点总结#

  1. 可执行文件格式：

    • Linux：ELF格式，包含代码段(.text)、数据段(.data/.rodata/.bss)等
    • Windows：PE格式，结构类似但细节不同

  2. 进程创建双重机制：

    • fork()：复制当前进程（写时复制优化）
    • execve()：用新程序替换当前进程

  3. 内存映射延迟加载：

    • ELF文件被映射到虚拟地址空间
    • 实际代码/数据在首次访问时通过缺页异常加载

  4. 系统调用桥梁作用：

    • 用户态程序通过系统调用请求内核服务
    • 内核通过中断/异常机制接管CPU

  5. 硬件软件协同：

    • 硬件：CPU状态切换、MMU地址转换、中断控制器
    • 软件：内核处理异常、驱动控制设备

这个简单的Hello, World!程序背后，是操作系统几乎所有核心子系统（进程、内存、文件、设备）的协同工作，完美体现了计算机系统的复杂性和精妙设计。
