一、基本概念与并发环境#

1. 进程并发执行的特征#

  • 顺序环境：
    • 程序独占资源，执行顺序性、封闭性、结果确定性。
  • 并发环境：
    • 执行结果不可再现
    • 程序执行是间断的
    • 资源共享
    • 进程间既有独立性又有制约性
    • 程序错误可能偶然发生

2. 竞争条件（Race Condition）#

  • 多个进程读写共享数据，最终结果取决于执行的时序。
  • 导致与时间有关的错误，如银行账户操作、缓冲区读写错乱。

二、进程互斥（Mutual Exclusion）#

1. 临界资源与临界区#

  • 临界资源：一次只允许一个进程使用的资源（如共享变量、文件）。
  • 临界区：进程中访问临界资源的代码段。

2. 临界区使用原则#

  • 有空让进
  • 无空等待
  • 有限等待
  • 多中择一
  • 让权等待

3. 实现互斥的方案#

  • 软件方案：

    • Dekker算法（第一个正确解）

      P: 
... ... 
pturn = true; 
while (qturn) { 
	if (turn == 2) { 
		pturn = false; 
		while (turn == 2); 
		pturn = true; 
		} 
	} 
	临界区 
	turn = 2; 
	pturn = false; 
	... ... 

      Q: 
... ... 
qturn = true; 
while (pturn) { 
	if (turn == 1) { 
		qturn = false; 
		while (turn == 1); 
		qturn = true; 
		} 
	} 
	临界区 
	turn = 1; 
	qturn = false; 
	... ...

    • Peterson算法（常用且简洁）

      
#define FALSE 0
#define TRUE  1  
#define N     2  // 进程的个数
int turn;        // 轮到谁？
int interested[N];  // 兴趣数组，初始值均为FALSE

      // process = 0 或 1
void enter_region(int process) {
int other;                   // 另外一个进程的进程号
other = 1 - process;
interested[process] = TRUE;  // 表明本进程感兴趣
turn = process;              // 设置标志位
while (turn == process &&
interested[other] == TRUE);  // 循环
}



      
void leave_region(int process) {
    interested[process] = FALSE;  // 本进程已离开临界区
}

      

      进程i:
…
enter_region(i);
临界区
leave_region(i);
…

  • 硬件方案：
    • 屏蔽中断（单处理器有效）
    • TSL/XCHG指令（适用于多处理器）
      TSL指令
      enter_region:
  TSL REGISTER, LOCK    // 复制锁到寄存器并将锁置1
  CMP REGISTER, #0      // 判断寄存器内容是否是零?
  JNE enter_region      // 若不是零，跳转到enter_region
  RET                   // 返回调用者，进入了临界区
leave_region:
  MOV LOCK, #0          // 在锁中置0
  RET                   // 返回调用者
      XCHG指令
      enter_region:
  MOV REGISTER, #1      // 将寄存器设置为1（表示要加锁）
  XCHG REGISTER, LOCK   // 原子交换寄存器和LOCK变量的值
  CMP REGISTER, #0      // 判断交换前LOCK的值是否为0
  JNE enter_region      // 如果不是0，说明锁已被占用，继续循环等待
  RET                   // 获得锁，进入临界区
leave_region:
  MOV LOCK, #0          // 释放锁，将LOCK置0
  RET

4. 忙等待与自旋锁#

  • 进程在等待进入临界区时持续测试，不释放CPU。
  • 适用于多处理器系统，但可能导致优先级反转。

三、进程同步（Synchronization）#

1. 同步概念#

  • 多个进程按某种时序合作完成任务。
  • 一个进程需等待另一进程提供消息，否则进入阻塞。

2. 经典同步问题#

  • 生产者/消费者问题（有界缓冲区）
    • 信号量解法：mutex、empty、full
  • 读者-写者问题
    • 第一类：读者优先
    • 信号量或管程实现

四、信号量与PV操作#

1. 信号量定义#

  • 一个整型变量 + 等待队列
  • 操作：初始化、P（wait）、V（signal）
  • 原语操作，不可中断

2. PV操作定义#

  • P(S)：S--，若 <0 则阻塞
  • V(S)：S++，若 ≤0 则唤醒一个等待进程

3. 应用#

  • 互斥：信号量初值为1
  • 同步：信号量初值为0或N（资源数量）

五、管程（Monitor）#

1. 管程定义#

  • 一个模块，包含共享数据及操作过程。
  • 进程只能通过调用管程过程访问共享数据。

2. 管程特点#

  • 编译器保证互斥进入
  • 内部使用条件变量实现同步
  • 支持 wait 和 signal 操作

3. Hoare管程 vs MESA管程#

  • Hoare：signal 后立即切换进程
  • MESA：signal 后继续执行，等待进程在条件满足时重新检查（使用 while 而非 if）

4. 广播（Broadcast）#

  • 唤醒所有在条件变量上等待的进程
  • 适用于不确定唤醒哪个进程的场景

六、锁与条件变量#

1. 锁（互斥量）#

  • 两种状态：加锁 / 解锁
  • 操作：lock()、unlock()
  • 适用于用户级线程包

2. Pthreads同步机制#

  • 互斥量：pthread_mutex_*
  • 条件变量：pthread_cond_*
  • pthread_cond_wait 会自动释放锁并等待信号

七、进程通信（简要梳理）#

1. 为什么需要通信机制？#

  • 信号量与管程在分布式/多处理器中受限
  • 进程间需要传递更多结构化信息

2. 基本通信方式#

  • 消息传递
  • 共享内存
  • 管道
  • 套接字
  • 远程过程调用
