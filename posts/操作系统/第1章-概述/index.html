一、 典型的操作系统架构#

  1. Windows架构

    • 用户态：
      • 系统支持进程（如：登录进程 Winlogon）
      • 服务进程（如：假脱机服务 Spooler）
      • 应用程序
      • 环境子系统（如：Win32）
    • 内核态：
      • 系统服务分发器
      • 执行体
      • 内核
      • 设备驱动程序
      • 硬件抽象层 - 将内核与特定硬件差异隔离开
    • 关键点： 模块化、分层设计。

  2. UNIX架构（经典分层结构）

    • 用户层： 应用程序、库函数
    • 系统调用接口： 用户态进入内核态的桥梁
    • 内核层：
      • 文件子系统： 管理文件，通过 Buffer Cache 与块设备交互。
      • 进程控制子系统： 负责进程调度、通信、内存管理。
    • 硬件控制

  3. Android架构

    • Applications： 应用软件
    • Application Framework： 提供API（如Activity Manager）
    • Libraries： C/C++库（如SQLite, OpenGL）
    • Android Runtime： 核心库与虚拟机
    • Linux Kernel： 提供核心系统服务（安全、内存、进程、驱动）

二、 操作系统是什么？#

  1. 定义

    • 操作系统是系统软件，是程序模块的集合。
    • 目标：有效、合理地组织管理计算机软硬件资源，控制程序执行，向用户提供服务。

  2. 三个作用与目标

    • 资源的管理者 → 有效
    • 向用户提供各种服务 → 方便使用
    • 机器的扩展（虚拟机） → 扩展能力

  3. 设计与实现目标

    • 抽象、性能、保护、可靠性、节能、安全性、移动性。

三、 认知操作系统的三种角度#

  1. 资源管理的观点（自底向上）

    • 管理硬件（CPU、内存、设备）和软件（文件）资源。
    • 实现资源共享，提高利用率（通过时间和空间复用）。
    • 内核五大功能：
      • 进程/线程管理
      • 存储管理
      • 文件管理
      • 设备管理
      • 用户接口

  2. 进程的观点（动态运行）

    • 操作系统是由并发运行的进程和一个对其进行协调的核心组成。
    • 进程：程序的一次执行过程，是动态的、有生命的。

  3. 虚拟器观点（内部结构） 操作系统通过分层结构，每一层构建一个虚拟器，逐层扩充功能，最终形成一个完整的操作系统虚拟机。

四、 操作系统的特征#

  1. 并发

    • 处理多个同时性活动的能力。
    • 宏观上同时，微观上交替执行（单CPU）。
    • 与并行（硬件支持）区分。

  2. 共享

    • 资源被多个用户或进程共同使用。
    • 方式：互斥共享（如打印机）、同时访问（如磁盘文件）。

  3. 虚拟

    • 将物理实体映射为多个逻辑实体，提高资源利用率。
    • 例如：虚处理机、虚拟内存、虚拟终端。
    • 虚拟机管理器（VMM） 是虚拟技术的典型代表。

  4. 随机性

    • 操作系统必须随时对不可预测次序发生的事件进行响应。

五、 操作系统的发展历程#

  1. 第1阶段 (1948-1970)：大型机时代

    • 特点：硬件昂贵。
    • 技术：批处理 → 多道程序设计 → SPOOLING技术（提高设备利用率）。

  2. 第2阶段 (1970-1985)：分时与交互时代

    • 特点：硬件便宜，人工昂贵。
    • 技术：分时系统（如CTSS）。
    • 目标：及时响应。
    • 著名项目/系统：CTSS（第一个分时系统），MULTICS（过于复杂，失败案例），UNIX（Ken Thompson, Dennis Ritchie，成功案例）。

  3. 第3阶段 (1981-)：个人计算时代

    • 特点：PC普及，OS从简单监控程序演变为功能齐全的复杂系统。

  4. 第4阶段 (1981-)：分布式时代

    • 核心：网络，实现资源共享。

  5. 第5阶段 (1995-)：移动计算时代

    • 特点：设备小型化、移动化。

  6. 第6阶段 (2006-)：云计算时代

    • 云计算OS：管理海量硬件资源，实现“治众如治寡”。

  7. 第7阶段 (200?-)：泛在计算/物联网时代

    • 特点：无数联网设备提供个性化服务。

六、 操作系统的分类#

  1. 批处理操作系统

    • 用户脱机工作，作业成批处理。
    • 分类：单道批处理 vs 多道批处理（显著提高资源利用率和吞吐率）。

  2. 分时操作系统

    • 多个用户通过终端共享主机，以时间片轮转方式提供服务。
    • 追求目标：响应时间。
    • 通用操作系统 = 分时（前台） + 批处理（后台）。

  3. 实时操作系统

    • 在严格时间范围内响应外部事件。
    • 分类：硬实时系统（绝对满足时限，如工业控制）、软实时系统（偶尔可违反时限，如订票系统）。
    • 追求目标：高可靠性、及时性。

  4. 网络操作系统

    • 在各自独立OS之上，按网络协议开发，实现通信和资源共享。

  5. 分布式操作系统

    • 统一的OS，多台计算机协同完成一项任务，对用户透明。
    • 需要解决问题：透明性、资源调度、一致性、容错等。

  6. 嵌入式操作系统

    • 运行在嵌入式系统中，完成特定功能，通常对实时性有要求（如TinyOS）。

  7. Tanenbaum分类

    • 大型机OS、服务器OS、多处理机OS、PC OS、实时OS、嵌入式OS、智能卡OS（极端资源限制）。

七、 关键技术与概念小结#

  • SPOOLING技术： Simultaneous Peripheral Operation On-Line。利用磁盘作为输入/输出井，实现I/O操作与CPU计算的并行。现代应用：打印队列。并未过时。
  • Buffer Cache： 位于文件子系统与块设备之间，缓存磁盘数据，减少I/O次数，提高性能。
  • 多道程序设计： 多个程序同时装入内存，交替执行，充分利用CPU。是现代操作系统的基础。
  • 重要历史系统：
    • OS/360： 早期大型OS，因过于复杂成为失败案例。
    • MULTICS： 理念超前但失败，催生了UNIX。
    • UNIX： 简洁、高效，由Ken Thompson和Dennis Ritchie开发，是现代操作系统的基石。
